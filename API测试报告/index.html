桌面端「数据备份与恢复」的恢复流程实际不可用；虽然失败后已自动回滚且数据未被破坏，但用户无法通过备份恢复数据。查看证据页

P2连续备份文件名秒级冲突，后一次覆盖前一次
同一秒内连续创建两次备份，两次返回的文件名完全相同（knowflow-backup-20261122-195359.zip）。
用户快速连续备份时，前一个备份会被静默覆盖，造成备份丢失。查看证据页
查看截图
P2未知 API 路径返回 200 HTML，而不是 404 JSON
GET /api/v1/unknown-endpoint 返回 200 与前端 index.html；备份路径穿越请求也因此返回 200 HTML。
API 客户端无法通过状态码区分「接口不存在」与「成功」；错误处理与监控会被误导。备份文件本身未被泄露。查看证据页

P3文档详情接口未回填 index_status
索引已完成时，GET /api/v1/documents/{id} 返回 index_status='unknown'，而列表接口返回 'indexed'。
同一资源在不同接口中的字段不一致，依赖详情页展示索引状态的场景可能误判为未知状态。查看证据页
