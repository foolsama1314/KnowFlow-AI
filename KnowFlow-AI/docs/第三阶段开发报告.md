## 一、完成的功能

### 3.1 知识库管理完善

- 文档列表补充 `index_status`（已索引/待索引/处理中/失败）与 `last_error`，失败原因来自最近一次失败任务，批量查询避免 N+1。
- 新增 `GET /documents/index-summary`：资料总数、解析完成、失败、待索引、文本块总数、已索引块数、索引状态、运行中任务数。
- 重建索引增加可轮询进度：`running/processed/total/stage/error`，接口 `GET /search/reindex/status`。
- 删除文档沿用既有实现：同步删除 Qdrant 向量、SQLite 页面/块/切块并同步索引计数。
- 失败文档可重新处理；空文件、重复文件、损坏文件均返回明确中文提示。
- 前端资料页新增索引概览、索引列、失败原因 tooltip、重建确认与进度条。

### 3.2 多文档智能分析

- 新增 `analysis_service.analyze`：对 1–8 份已完成文档逐篇限定检索，不拼接全文。
- 输出固定小节：共同观点、差异分析、关键知识点。
- 上下文按 `rag_context_chars` 与每篇 `top_k` 控制，超长时标记 `truncated` 并提示。
- 无命中或最高相似度低于阈值时直接拒答，不调用模型。
- 引用编号由服务端校验，越界编号剔除；引用对象带文件、页码、相似度与 cited 标记。

### 3.3 智能总结

- 与多文档分析共用服务，`POST /analysis/summary` 固定总结模式。
- 输出核心观点、关键概念、重要结论、待研究问题；缺失小节补“资料不足，无法判断”。
- 支持单篇与多篇，总结内容可追溯到原文与页码。

### 3.4 AI 研究报告

- 新增 `report_service.generate`：主题 + 文档选择 → 逐篇检索 → 真实 LLM → 结构化报告。
- 报告小节：研究背景、核心内容、关键发现、综合分析、结论、参考资料。
- 参考资料只列出回答实际引用的资料，显示文件名与页码。
- 软件内预览；导出 Markdown（字符串组装）与 DOCX（复用已有 `python-docx`），未新增依赖。
- 报告文件持久化到 `data/exports/reports/<report_id>.{json,md,docx}`，支持历史列表、重新预览与下载。
- 报告 ID 严格校验，防止路径穿越。
- 未配置 LLM、资料不足、上下文截断、导出失败均有明确提示。

### 3.5 系统设置完善

- 新增 RAG 参数读写：`rag_top_k`、`rag_min_score`、`rag_context_chars`，持久化到 `data/settings.json`。
- 设置页新增 RAG 面板、功能可用性提示（Embedding/LLM 未配置时说明不可用功能）。
- 模型配置与连接测试沿用既有实现；API Key 仅返回 `has_key`，不回传明文。
- 默认拒答阈值根据真实测试从 0.35 调整为 0.50（见第四节）。

### 3.6 数据备份与恢复

- 新增 `backup_service`：
  - SQLite 使用 `sqlite3.backup()` 一致性快照，不直接复制运行中的 db。
  - 本地 Qdrant 复制数据目录（忽略 `.lock`）；服务模式通过 `scroll` 导出点数据。
  - 上传文件原样打包；配置默认剔除 `llm_api_key`/`embedding_api_key`。
  - `manifest.json` 记录格式版本、创建时间、Qdrant 模式、文档/文本块数量、文件 SHA256。
- 恢复流程：校验 → 自动生成 `pre-restore-*.zip` → 解压 → 关闭 Qdrant/释放数据库连接 → 原子替换 → 校验失败或异常回滚。
- 未包含 Key 的备份恢复时，保留本机现有 Key。
- 有运行中任务时拒绝备份/恢复，避免 SQLite 与 Qdrant 不一致。
- 前端设置页新增备份列表、创建（可选包含 Key，二次确认）、校验、恢复（二次确认）与下载。

### 3.7 UI 与交互完善

- 新增「多文档分析」「研究报告」导航与页面。
- 新页面包含空状态、加载状态、错误提示、拒答提示、截断提示。
- 所有危险操作（删除资料、重建索引、恢复数据、包含 Key 备份）均有确认框。
- 引用列表区分「已引用 / 仅检索到」，点击跳转文档页码。
- 未重写已稳定的问答、检索、文档详情页面。

### 3.8 异常处理和稳定性

- 新增桌面启动可写检测：`data` 目录不可写时弹窗提示并退出，不显示 Python 堆栈。
- 模型未配置、Key 无效、额度不足、网络错误、超时均转为中文 `AppError` 提示。
- 文档解析/索引失败写入任务与文档状态，可在资料页看到原因并重处理。
- SSE 中断沿用既有保存逻辑；退出时关闭向量客户端与任务执行器。

## 四、真实模型测试结果

### 4.1 Embedding（真实）

- 模型：DashScope `text-embedding-v3`，1024 维，OpenAI 兼容协议。
- 状态：**已真实验收**。EXE 中完成文档解析、向量化、索引重建、语义检索与恢复后检索。

真实检索分数记录（演示知识库）：

| 问题 | top1 | 最高命中文档 | 判断 |
| --- | --- | --- | --- |
| RAG 的核心流程是什么 | 0.7102 | RAG技术概览.pdf 第 1 页 | 明确命中 |
| 知识管理对企业的价值 | 0.5526 | 课程笔记.txt | 弱相关 |
| 量子纠缠实验的测量方法 | 0.4964 | RAG技术概览.pdf 第 3 页 | 完全无关 |

结论：0.35 无法拒绝完全无关问题（0.4964 > 0.35），因此将默认拒答阈值调整为 **0.50**，并保留设置页可调。该结论来自真实检索结果，未伪造分数。

### 4.2 LLM（真实）

- 状态：**真实模型验收未完成**。
- 原因：本机未配置可用 LLM Key；此前调用 qwen-plus / qwen-flash 返回 403（FreeTierOnly 额度限制），qwen-turbo 返回 429（限流）。
- 已完成：LLM 未配置时的明确提示、调用链路、引用校验、错误收敛；分析/问答/报告链路已用真实检索 + 测试替身模型验证结构正确性。
- 待办：用户在「系统设置」配置真实 LLM 后，重新执行问答、多文档分析、智能总结、研究报告四项验收，并人工检查回答质量与引用准确性。

> 未将任何模拟服务结果标记为真实模型验收通过。

## 六、已知问题

1. **真实 LLM 验收未完成**：受额度/Key 限制，问答、分析、总结、报告的真实模型输出质量尚未验收。
2. **异常退出后立即重启可能遇到 Qdrant 文件锁**：强制结束进程后立即重启，可能提示“已经被另一个实例占用”；等待旧进程完全退出后重启即可。正常关闭窗口不会出现。
3. **恢复期间需空闲**：有文档处理任务时备份/恢复会被拒绝，这是为保护数据一致性做的限制。
4. **交付数据未配置 Embedding**：首次配置 Embedding 后，索引状态可能提示需要重建，按界面提示点击「重建向量索引」即可。
5. **报告历史仅展示最近 20 份**，暂无删除报告入口；报告文件位于 `data/exports/reports/`。
6. **分析/总结结果不落库**：按设计直接返回，不新增数据库表；只有研究报告落盘。
7. **大资料量性能未压测**：当前演示知识库规模较小，数百份文档以上的检索延迟与上下文策略未验证。
8. **服务模式 Qdrant 备份**：以点数据 JSON 导出，数据量大时备份文件会明显增大。
